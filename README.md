# Kanban

Канбан-доска в духе Trello. Проект для практики во фронтенд-разработке: управление состоянием, работа с сервером, производительность, командная работа в реальном времени и архитектура приложения.

## Стек

- React + TypeScript (strict)
- Vite
- Zustand: состояние интерфейса
- Vitest + Testing Library: тесты
- ESLint + Prettier: качество кода
- Steiger: проверка архитектурных правил FSD

## Запуск

```bash
npm install
npm run dev
```

## Архитектура: Feature-Sliced Design

Проект организован по методологии [Feature-Sliced Design](https://feature-sliced.design/).

```
src/
├── app/                     инициализация: App.tsx, main.tsx, провайдеры, глобальные стили
├── pages/
│   └── board/               страница доски
├── widgets/
│   └── board/               собранная доска: колонки и карточки
├── features/
│   ├── move-card/           перетаскивание карточки
│   └── card-form/           форма создания и редактирования карточки
├── entities/
│   ├── board/               типы и стор Zustand, тесты стора
│   ├── column/              компонент колонки
│   └── card/                компонент карточки
└── shared/
    ├── ui/                  базовые компоненты: кнопки, поля, модалки
    ├── lib/                 общие хуки и утилиты
    └── config/              конфигурация
```

### Правила

- **Слой импортирует только из слоёв ниже.** Порядок сверху вниз: `app → pages → widgets → features → entities → shared`.
- **Слайсы одного слоя не импортируют друг друга.**
- **Внутри слайса** код делится на сегменты: `ui/`, `model/`, `api/`, `lib/`.
- **Снаружи слайс открыт только через `index.ts`** (публичный API). Импорты вглубь слайса запрещены.
- **Импорты идут через алиас `@`**, например `import { useBoardStore } from '@/entities/board'`.
- **Стор с данными доски лежит целиком в `entities/board`**, потому что действие `moveCard` затрагивает и колонки, и карточки.
- **Тест лежит рядом с тем, что тестирует**, с суффиксом `.test.ts` или `.test.tsx`.

Проверка правил:

```bash
npx steiger ./src
```

## План

1. Фундамент: стор, доска, перетаскивание, формы, тесты
2. Данные с сервера: мок API, TanStack Query, оптимистичные обновления
3. Производительность: виртуализация, замеры, свои алгоритмы
4. Системный дизайн: realtime, offline-first, конфликты
5. Продакшн-уровень: доступность, e2e, CI, деплой
